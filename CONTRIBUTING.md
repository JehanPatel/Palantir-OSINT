# Contributing Guidelines

First off, thank you for considering contributing to this project!

The following is a set of guidelines for contributing to this repository. These are mostly guidelines, not rules. Use your best judgment, and feel free to propose changes to this document in a pull request.

## Code of Conduct
By participating in this project, you are expected to uphold a welcoming and respectful environment. Please direct any concerns or unacceptable behavior to the repository maintainers.

## How Can I Contribute?

### Reporting Bugs
Before creating bug reports, please check the existing issues as you might find out that you don't need to create a new one. When you are creating a bug report, please include as many details as possible:
* Use a clear and descriptive title.
* Describe the exact steps which reproduce the problem in as many details as possible.
* Provide specific examples to demonstrate the steps.
* Describe the behavior you observed after following the steps and point out what exactly is the problem with that behavior.
* Explain which behavior you expected to see instead and why.

### Suggesting Enhancements
Enhancement suggestions are tracked as GitHub issues. When creating an enhancement suggestion, please provide the following information:
* Use a clear and descriptive title for the issue to identify the suggestion.
* Provide a step-by-step description of the suggested enhancement in as many details as possible.
* Describe the current behavior and explain which behavior you expected to see instead and why.
* Explain why this enhancement would be useful to most users.

### Pull Requests
* Fill in the provided pull request template if one exists.
* Include screenshots and animated GIFs in your pull request whenever possible for visual changes.
* Ensure your code passes all existing tests and add new tests for your features or bugfixes.
* Keep your commits focused and provide clear, descriptive commit messages.
* End all text files with a newline.

## Local Development Setup
To set up the project locally for development, please refer to the primary instructions provided in the repository's `README.md` file. It contains all the necessary steps for installation, environment setup, and running the application or tests. 

The standard workflow is:
1. Fork the repository and clone your fork.
2. Follow the setup instructions in the `README.md`.
3. Create a new branch for your feature or bug fix.
4. Commit your changes and push the branch to your fork.
5. Submit a pull request.

## Styleguides

### Git Commit Messages
* Use the present tense ("Add feature" not "Added feature").
* Use the imperative mood ("Move cursor to..." not "Moves cursor to...").
* Limit the first line to 72 characters or less.
* Reference issues and pull requests liberally after the first line.
* Consider using [Conventional Commits](https://www.conventionalcommits.org/) (e.g., `feat:`, `fix:`, `docs:`).
